📘 Qué documentas (y qué no)
1️⃣ Contexto (breve, pero real)

Para quién era el sistema

En qué entorno vivía

Qué dolía de verdad

Ejemplo:

El problema no era agendar citas, sino reducir fricción operativa en negocios con poco tiempo y cero infraestructura digital.

2️⃣ Restricciones (oro puro)

Aquí te diferencias de 90 % de portfolios.

Tiempo

Infraestructura

Usuarios reales

Costos

Legacy / caos

Esto muestra que no trabajas en el vacío.

3️⃣ Decisiones clave (el corazón)

No todas. Las importantes.

Ejemplo:

Por qué microservicios y no monolito

Por qué este stack y no otro

Por qué automatizar X y no Y

Qué trade-off aceptaste

Cada decisión responde a:

“Dado esto… decidí esto…”

4️⃣ Sistema / Arquitectura (abstracto, no tutorial)

Diagrama limpio

Flujos

Componentes

Responsabilidades

No código.
Sistema.

5️⃣ Qué salió mal (obligatorio)

Esto es nivel senior.

Algo que no escaló

Algo que sobre-ingenierizaste

Algo que subestimaste

Sin drama. Sin excusas.

6️⃣ Impacto / Resultado

No métricas falsas.

Puede ser:

Se usa

Reduce tiempo

El sistema vive

Se volvió base para otros proyectos

7️⃣ Qué harías distinto hoy

Esto muestra evolución.

Ejemplo:

Hoy simplificaría X y movería Y a otro servicio, porque ahora entiendo mejor Z.
